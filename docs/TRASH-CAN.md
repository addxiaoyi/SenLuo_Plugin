# 垃圾桶移植（2026-11-17）

后续动画更新见 [来源动画](TRASH-CAN-ANIMATION.md)；下文三部件与旧动画差异描述保留为 trashcan-v1 历史状态。

固定来源：KaleidoscopeCookery `2f4e386ce23f49a385ddf003c67fc6415c55417a` 的 `TrashCanBlock`、`TrashCanBlockEntity`、`TrashCanModel`、渲染器和动画。此文记录当前实现及仍待完成的差异，不代表完整复刻验收。

主手持物右键放入整组，优先合并完整组件相同的物品，再填空格。三格都放不进去时，丢弃第一格，把后两格前移，新物品放最后一格；能放入部分时只扣对应数量，不挤掉旧物。创造模式也扣物，与来源一致。空手普通右键不取物；空手潜行右键取回最后一个非空槽的整组，直接放主手。修复了此前潜行会清空、按 ID 合并不同名称/附魔，以及创造模式不扣物的问题。原有 `clearStorage()` 管理 API 保留，但玩家点击不再调用它。

红石邻居供电时，每 tick 查询桶顶 `y+15/16..y+1` 的掉落物。只有桶内已存在同类物品才处理：尝试填充第一个匹配槽，然后销毁整个掉落实体。首个槽已满、只能容纳一部分、组件不同，都仍会销毁该同类实体；不会接着填第二个槽。这是来源 `hasItem`/`entityInside` 的实际行为。没有滤材、未通电、不同物品 ID 或不在吸取区域的实体均保留。自定义 CE 物品按自定义 ID 区分，避免不同自定义纸物品互相充当滤材；这是对模组独立物品注册的适配。

存储使用原生完整物品组件。写入前校验三槽数据及 CE 持久化编码，拒绝无法保存的输入。主副手、旁观者、区域所有权、保护权限、无效家具和重入均有检查；公开库存返回深拷贝。坏档、重复槽、越界槽、无法解码物品不会被当成空桶重写，原始数据继续保存。拆除后的 `postRemove` 才发放库存，重复回调不重复发放；掉落事件取消时，剩余库存写到厨房插件数据目录 `recovery/trash-can-*.nbt`，不自动返还，需管理员核对后恢复。

资源包包含可合成、可放置的 `kaleidoscopecookery:trash_can`、三个动画显示物品及仅发包的假头盔。合成配方是八个铁锭围绕堆肥桶，厨房已导入配方计数为 **611/612**，剩余为稻草人。三个显示模型按 Java 来源转换七个立方体/平面，保留层级偏移、把手的 -90° 旋转和逐面 UV；零面积侧面省略。物品展示模型仍使用来源 item JSON，放置模型使用来源 Java 几何，两者的把手方向本来就不同。

1.21.2–26.3 的假头盔配置独立 `equippable.camera_overlay` 并引用原始遮罩 PNG；1.21.1 缺少该组件，导出时删除，仅保留普通南瓜遮罩。没有全局覆盖原版南瓜贴图。`tools/check_trash_can_models.py` 核对最终生成资源包的几何、纹理字节、配方与版本组件；它不证明客户端实际显示。

剩余实现与验收：

- 当前仍使用无实体碰撞的 CE interaction 箱，无法复现来源实体碰撞体；从桶上方落下的躲藏仍依赖下方着陆面。水浸、活塞、爆炸和来源硬度未实现。
- 躲藏沿用旁观相机与假头盔，而来源使用乘坐实体；保护取消、切模式/传送取消、死亡/退出和客户端第一人称效果需真人验证。
- 动画仍是既有线性插值和取整 tick；来源 Catmull-Rom、独立眼皮移动及精确关键帧未完全复刻。视线中的库存 HUD 暂以世界中的掉落物展示替代。
- Folia 邻区所有权不足时跳过吸取，尚无 Folia 实测；多人、保护插件、客户端渲染和中间版本运行也未完成验收。

针对性 Java 测试验证交互、组件隔离、部分插入/挤出、来源红石筛选、非法存档和重入。实服探针直接用已安装插件的 NBT API 建立库存，随后使用真实红石、物品实体、世界存档、CE 拆除和 Bukkit 掉落取消事件；它不模拟真人点击。最终轮次与产物哈希以本批 `docs/research/trashcan-runtime-2026-11-17.json` 和构建记录为准。

实服结果：g/21–22（Paper 1.21.1）和 h/14–15（Paper 26.3）各八组报告通过、资源生成成功并正常停服；第一轮保存三组物品，第二轮恢复/拆除/取消回收通过。g 两轮无错误行；h 每轮两条 Windows OSHI 性能计数器错误仍保留。客户端与完整躲藏不在探针范围内。
