# Deco 模型状态检查点（2026-11-17）

固定来源为 KaleidoscopeDeco `6ce180e1226ce93b0fb0d45ea80e0ed5b01b1dc0`。导入器现在递归解析物品模型树中的 custom_model_data 字符串、布尔和浮点分支。此前苹果盘等模型在显示场景选择器内部仍保留浮点选择，而 CraftEngine 会重新分配 CMD 编号，导致剩余份数模型错误。当前在导入时固定来源状态，保留显示场景和其他实时条件。

家具使用 221 个内部显示物品，使背包图标与摆放模型分别使用正确分支。内部物品不加入玩家目录，家具取回仍保持原始物品身份。共导出 1,075 个物品定义、785 种家具、2,263 个变体；家具 ID 集合与前序一致。751 个物品声明了六种常用场景一致的旧版模型。来源绵羊玩偶的 `[1,1,1]` 颜色显式转换为小数格式，避免 CE 将其当作字节颜色并生成接近黑色的结果。

## 实际验收

Paper 1.21.1-133 / Java 21 与 Paper 26.3-253 / Java 25，运行 CraftEngine 26.9.2。用户已接受 EULA，测试只监听 127.0.0.1，顺序运行。两端最终轮次 g/11、h/5 的六组探针均无失败：

- Deco 全部 1,075 物品构建、身份和原生序列化通过；785 家具及 2,263 变体的注册、显示物品引用通过。
- 11 个苹果盘、油罐、茶壶和沙发样本完成摆放、92 次 CE 变体切换、掉落物身份检查，并在重启后全部恢复。
- 前序五组厨房探针继续通过，包括 1,422 物品和 24 个厨具的恢复。
- 两端资源包生成和 ZIP CRC 通过。逐项检查实际输出：26.3 的 1,075 个现代模型一致；1.21.1 的 1,041 个现代模型和 1,040 个可直接比较的旧版模型一致。绵羊默认色恢复为 `[1.0,1.0,1.0]`。

工具为 `series/tools/check_deco_generated_models.py`，根据 CE 实际分配的 CMD 或现代 item-model 路径检查最终资源 ZIP。机器证据见 [deco-model-runtime-2026-11-17.json](research/deco-model-runtime-2026-11-17.json)，包含实际 JAR 哈希、六组报告、安装内容逐文件比对和保留的警告。

## 明确限制

1.21.1 的旧模型转换警告从 229 降至 37：34 个 Deco、3 个 Cookery。剩余 Deco 包括复合模型、不同显示场景使用不同几何的酒瓶/茶壶；CE 在旧服生成资源时也会省略这些条目的现代 CMD 分支。不能把资源工作流成功理解为这些物品显示已修复。

显式旧版模型只证明背包、掉落物和四种持有场景一致；头部、物品展示框、on_shelf 等场景未宣称完全复刻。绵羊在旧版的着色未做等价验证。缺失来源纹理/模型、26.3 玩偶 UV 越界、CE 默认棕榈树配置错误仍保留。

g/9 的前四个苹果盘在测试区块边缘切换遭拒；检查存档后确认支撑上方为空气。探针移到独立区块 12 的内部，保留正常碰撞检查后通过。失败实体和日志原样保留；此修正是测试布局修正，不是跨区放置行为的完成证明。

本轮使用 CE 服务端 API，未模拟玩家点击，也没有客户端截图或当前 Folia 验收。188 条聚合导入限制仍在 `series/docs/deco-import.json`；从旧数值下降主要来自模型解析修复，不代表新增同等数量玩法。完整复刻目标仍未完成。
