# 带内容蒸笼开发检查点

2026-11-17，固定来源 `2f4e386ce23f49a385ddf003c67fc6415c55417a`。本批在固定槽位存档基础上实现蒸笼物品保存、叠放合并、分层掉落，以及两条带四件原料的来源合成。当前是开发构建，实服和原版客户端尚未验证。

蒸笼物品在 `minecraft:custom_data` 的 `kaleidoscopecookery:steamer_contents` 中保存四个物理槽。物品通过当前服务器的原生编解码保存，连同每槽进度、耗时、配方快照和暂停标记一起往返；不把来源 Forge 物品 ID 直接写进现代组件。非空蒸笼只能堆叠一件，空蒸笼恢复 64 件。写入使用独立副本，保留物品已有的其他 custom_data。旧 `BlockEntityTag`、原生 block_entity_data、歧义数据、非法数量或上层槽位会拒绝放置，尚未提供旧 Forge 物品迁移。

叠放时，现有槽 0–3 保留，手中蒸笼四槽写入 4–7。放置先验证和序列化，再经过冒险模式、区域归属、保护与放置事件检查，所有回调通过后才载入合并库存和扣一件物品。取消、原生写入异常、手中数量改变、玩家失效及回调改变库存都会阻止提交。回滚恢复下层状态；回调已替换目标方块时保留替换方块，原下层已被移除则退回一件带原内容的蒸笼。事务期间禁止重复放置、控制器加工与放取。

新导出包启用 `portable_contents: true`，移除普通空蒸笼 loot 和额外双层掉落行为，统一由控制器生成容器：半笼一件、双笼两件，各自保留对应四槽及时间。所有容器先构造成功，再清空原库存并发出掉落，重复/重入移除不会重复产物。创造模式、关闭方块掉落规则及下落实体接管时不重复掉容器；下落失败也按层封装。`SteamerBreakFullEvent` 取消时沿用现有语义，仅返回空容器。旧配置未开启 portable_contents 时保留旧散装掉落逻辑；升级必须同时安装本批 JAR 与 CE 配置。

`raw_dough_steamer` 与 `stuffed_dough_food_steamer` 使用正常无序合成：一件蒸笼和四个独立原料槽，输出一件装有四件原料的蒸笼。每槽从 0 开始，耗时固定为来源的 1,200 tick，避免误用厨具默认的 200 tick。导出器逐字段校验来源 JSON 与 SNBT，新增或改变的载荷直接报错。完整厨房现为 610/612 来源配方已导入，剩余稻草人与垃圾桶；原版/合成配置 140 条。
