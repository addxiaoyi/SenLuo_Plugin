# 挂鱼勾玩法与复合模型（2026-11-17）

固定来源为 KaleidoscopeDeco `6ce180e1226ce93b0fb0d45ea80e0ed5b01b1dc0` 的 `kaleidoscope_cookery_plus`。来源是三格展示架：接受鳕鱼、熟鳕鱼、鲑鱼、熟鲑鱼、热带鱼，后放入的先取出；没有风干或烹饪计时。实现保留单条鱼的完整原生物品组件。

主手持鱼放入一条，空手取出最后一条。生存模式放入扣除当前手持格的一条鱼；创造模式不扣鱼，取鱼时也不生成奖励。三格满时不扣物。掉落事件取消时取出失败并恢复展示，避免吞物或复制。超出持久化大小上限的组件在扣物前拒绝。四个来源状态均拆出空鱼架，单次左键拆除，摆放和拆除使用来源木质音效。

已确认拆除后逐条返还原鱼；若掉落被其他插件取消，剩余内容写入 Deco 数据目录的 `recovery/*.nbt`，需要管理员处理，不自动发放。坏档拒绝操作并保留原始 NBT。重复 `postRemove` 不重复返还。鱼架不再被通用“内部有物品不能拆除”逻辑阻止；保护事件仍按 CE 流程执行。

CE 26.9.2 会在新实体进入世界前调用 `onLoad`，此时 `isValid=false`。鱼架在 `onPlace` 完成首次展示，并使用实体所属调度器处理区块恢复；延后任务核对当前控制器，避免重载后操作旧实例。存档数量、槽位类型和鱼种严格验证。

40 种有序外观包含空架、3 种单鱼、9 种双鱼、27 种三鱼。四个来源家具各增加这些变体，共 160 个。内部显示物品不加入目录。复合几何合并保持原始元素顺序、UV、旋转、父模型覆盖和纹理解析；不同显示变换、实时条件、着色器或不支持的父模型不会被近似合并。全 Deco 导出为 1,115 物品、785 家具、2,423 变体，聚合导入限制 186 条。

`series/tools/check_fishrack_models.py` 独立对照固定来源的全部 40 种几何与四张纹理，并检查最终生成资源包。该检查证明生成文件一致，不等同于客户端截图验收。旧版 1.21.1 的总模型转换警告从前序 37 降至 30（27 Deco、3 Cookery）；剩余复杂酒瓶/茶壶模型仍有缺口。

运行验收采用 Paper 1.21.1-133 / Java 21、Paper 26.3-253 / Java 25 和 CraftEngine 26.9.2，仅监听 127.0.0.1。最终 g/19、h/11 七组探针均通过，资源工作流成功并正常退出；26.3 的两条 ERROR 来自 Windows OSHI 性能计数器，插件探针无失败。详细结果见 [运行证据](research/fishrack-runtime-2026-11-17.json)。探针经已安装插件的公开控制器 API 检查真实物品生成事件，不代表真人点击、保护插件联动或 Folia 验收。
