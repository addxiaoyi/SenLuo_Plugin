# 蒸笼存档与叠放开发检查点

本页保留 steamer-state-v1 历史记录。后续带内容物品、分层掉落和两条合成已接入，当前进度见 [带内容蒸笼](STEAMER-PORTABLE.md)。

2026-11-17，固定来源 `2f4e386ce23f49a385ddf003c67fc6415c55417a`。本批修复现有蒸笼的内容保存、取物与叠放入口；带内容蒸笼的两条合成仍未启用。源码哈希和后续差异见 `research/cookery-steamer-state-audit-2026-11-17.json`。

槽位 0–3 固定为下层、4–7 为上层。新存档使用 inventory_schema=1 和带索引的 slots 列表，保留每槽物品、进度、耗时、固定配方和暂停标记；旧版紧密排列的 items 数据仍可读取。取物不再把上层物品移到下层，放料填入首个空槽。取出多件成品时返回整个槽内堆叠，修复旧实现返回一件后丢弃其余物品的问题。新存档无法被旧插件版本读取，回退时需要使用升级前的存档备份。

加载先验证全部物品、槽位、数组、元数据和配方，再替换运行状态。重复/越界槽位、坏物品、不支持的格式、缺失字段或损坏配方不会静默清空或错配进度；原始坏数据会原样保存在下一次保存中，停止该控制器的加工、放取及内容掉落。空存档会清除旧库存、盖子和火力。这个保护只覆盖控制器的数据处理，不能保证第三方强制删块后仍能恢复整个方块。

移除前先转移库存所有权，重复或重入掉落回调不会重复产物。计时器使用 CE 传入的当前控制器，避免热重载后继续调用旧实例。显示按实际槽号更新，各玩家的生成/移除由已有 ItemDisplaySet 管理；加载后首 tick 刷新。盖子读取当前方块属性，避免相邻蒸笼去盖后仍按旧缓存加工。下落失败路径也能读取新旧两种存档，但仍按现有逻辑掉散装食物和空蒸笼。

叠放入口现在调用物品已注册的 BlockItemBehavior.place，由 CE 处理正常放置检查、事件、取消回滚、物品数据读取和最终扣料。测试验证入口传递成功/取消结果且没有额外扣物；实际保护插件、回调改变方块、跨区域和下落过程仍需实服验证。

新增 20 项 Java 测试：17 项控制器、1 项稀疏显示、2 项放置入口。旧实现运行最初 12 项时失败 10 项，修复后通过；旧实现的 ticker 误用出现空指针、重复移除出现栈溢出。最初夹具触发 CE 运行时 Log4j 类缺失，改为模拟空物品；扩大测试时的重载匹配编译错误也已修复。失败日志全部保留。最终厨房 515 项 Java 全量通过；系列 71＋4 旧 API 及 Python 136＋59 保留本批未改逻辑的前序通过记录。

剩余工作包括：用新版物品组件替换旧 BlockEntityTag 读取；放置前验证带内容物品；把新蒸笼四槽合并到上层并在取消时还原；按来源拆成一或两个携带食物和进度的蒸笼物品；一次取出全部、拆空层、副手交互、非热源放置、原始朝向/底座、碰撞、水浸、粒子及带内容模型。两条合成必须保留四件来源原料和 1,200 tick 耗时，不能直接套用默认 200 tick。
